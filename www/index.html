The problem

Every MCP call is uninspected by default.

Your AI agents are calling MCP servers right now. No access control. No audit trail. No threat detection.

No access control at the tool layer

Any agent that can reach an MCP server can call any tool with any arguments. No allowlists, no role restrictions.

No audit trail

No record of what your agents accessed or changed. When compliance asks, you cannot answer.

No threat detection

Prompt injection, data exfiltration, privilege escalation — nothing is detected until something goes wrong.

How it works

Transparent proxy. Zero client changes.

Step 1 — Install

Drop Sentinel between clients and servers

One config file. Your clients and servers stay exactly as they are.

Step 2 — Configure policies

Define who can call what in YAML

Deny-by-default. Hot-reload without restart. Policy changes are git-diffable.

Step 3 — Sentinel handles the rest

Every call is evaluated, logged, and scanned

Violations are blocked. Everything is queryable.

# sentinel.yaml
port: 4100
servers:
  - name: github
    transport: stdio
    command: npx -y @modelcontextprotocol/server-github

# policies/default.yaml
roles:
  analyst:
    rules:
      - allow: resources/read
      - allow: tools/call
        tools: [query_*, search_*, get_*]
      - deny: "*"
defaultRole: analyst
Features

Everything in the free tier. No limits.

RBAC Policy Engine

Declarative YAML. Deny-by-default. Hot-reload without restart. Write policies in PRs, roll back with git revert. Works like Kubernetes RBAC for MCP.

Audit Trail

Every call logged: who called what, with what arguments, allow or deny decision, latency. Export CSV or JSON for compliance teams. SQLite on-disk, no external database.

Security Scanning

Pattern-based detection for prompt injection, data exfiltration, and privilege escalation attempts. Configurable rule sets. Block on detection or flag-only mode.

Dashboard

Real-time traffic view, violations feed, audit search — served directly from Sentinel. No external service. No signup.

FAQ

Common questions

Does Sentinel add latency?
Under 2ms for the proxy layer in testing. Audit logging is async — it does not block request processing.
What MCP transports are supported?
Both. stdio for Claude Desktop and local servers. Streamable HTTP for remote servers.
Where does audit data live?
On your machine. Default path: ./data/sentinel.db (SQLite). No data leaves your infrastructure. Postgres is on the roadmap.
Can I contribute?
Yes. MIT license, PRs welcome. See CONTRIBUTING.md in the repo.
